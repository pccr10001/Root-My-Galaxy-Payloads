## Qualcomm handoff and P0

The exact `abl.elf.lz4` was decompressed to SHA-256
`d2bf34e7e5b17d4a2e7401ea439cb6617ab2c4fe98d74ab7c87d71167ccf5c4a`.
Its UEFI GUID-defined LZMA section contains the ARM64 LinuxLoader PE image.
LinuxLoader selects the ARM64 load constants `0x00080000` and `0x05600000`,
then adds the selected load offset to the lowest RAM base. With RAM at
`0x80000000` and the Image `text_offset` equal to zero, the profile uses:

```c
#define P0_PHYS_OFFSET 0x80000000ULL
#define P0_KERNEL_PHYS_LOAD 0x80080000ULL
```

`p0_fingerprint.h` was regenerated at probe offset `0x1f0000`. It contains
all 32 64-KiB slide candidates and was independently read back from the raw
Image: 256 of 256 qwords match.

## Runtime reclaim guard

The first manual app run leaked an order-3 `mm_struct` at object index 16,
then used the unconstrained 32-trigger late drain and rebooted. The app profile
therefore searches only indices 20 through 30, partitions the full direct-map
search exactly, and limits the late drain to two triggers. A low-slot candidate
now exits before reclaim rather than continuing into the unstable sequence.

The pipe-page KernelSnitch leak is a separate probabilistic setup step. The app
profile retries it up to 12 times in the same process, resetting its pipe state
between attempts; a failed pipe-page leak no longer consumes the whole app
attempt. The E1Q profile also enforces a 300-second P0 discovery timeout and a
360-second total-attempt timeout, because a successful pipe leak followed by
eight page-search retries can exceed the app's generic 45-second P0 watchdog.
After repeated hardware runs reported only `sk_buff` page leak failures, the
pipe-page setup was split from the slide-page KernelSnitch profile. E1Q now
uses pipe profile mode 2 with the stronger `4096/128/8` timing parameters for
that first pipe oracle leak, while later slide-page searches keep the shorter
`2048/64/8` profile.
